## 1. Главный тезис (одно предложение)

Один агент — это гений с гниющим контекстом; fleet — это конвейер, где контекст передаётся эстафетой по файлам, каждый агент получает ровно свой кусок, а правильность проверяется сигналом, а не верой.

## 2. Пять опор ядра

### О1. Контекст — эстафета, а не свалка (иерархия контекста)
- Один чат (Claude Code / Cursor) тащит всё в одном контексте: бизнес-требования из первого часа, скобку из прошлого часа, три своих галлюцинации. Context Rot — рюкзак один и он пухнет.
- Fleet: контекст живёт в файлах, не в чате. Бриф (.factory/briefs/) → доска (.factory/chats/) → отчёт (.factory/goals/). Каждый агент читает свой кусок — и только свой.
- Изоляция роли — технически (из analyst.md: inheritProjectContext: true, inheritSkills: false, maxSubagentDepth: 0, «субагентов не зовёт»): контекст скалируется по роли, скиллы не наследуются, глубина вызовов — ноль. Роль не может расползтись.
- Аргумент: «контекст течёт по файлам, а не по чату» — файл можно перечитать, передать, закоммитить, отдать следующему агенту. Чат — нельзя.

### О2. Граф вызовов вместо диалога с гением
- Директор (Hermes, SOUL.md) принимает заказ и решает: простой кейс — один исполнитель по таблице ролей, сложный — lead собирает состав. Бриф — вершина графа; из него — рёбра на роли; каждая роль пишет на доску; замыкает аудитор.
- Порядок зафиксирован: lead → analyst/designer/developer/tester → techwriter (если проект изменился) → auditor последним. PASS только после аудитора. Голый PASS не считается — нужны непустые «Изменения» и «HLD».
- Это не «много агентов» — это жёсткий граф. Мультиагентные бенефиты деградируют с масштабом (Scalability-Coordination Dilemma, свежий обзор 249 работ), поэтому выигрывает не количество агентов, а дисциплина связей.

### О3. Сигнал вместо веры (DoD + аудитор)
- DoD в брифе требует воспроизводимый сигнал: не «токены обновлены», а «вот вывод grep, вот номера строк». Аудитор не верит — он проверяет.
- Адверсариальность: аудитор специально пытается сломать работу коллеги (CSS-специфичность, prefers-reduced-motion, левые зависимости в package.json).
- Бюджет бреда: один FAIL — один повтор того же окна; второй FAIL — needs_decision, человек; третье окно не открывается. У саморефлексивной спирали нет шансов раскрутиться.

### О4. Дорогая модель только там, где код (экономика ролей)
- lead/analyst/designer/tester/techwriter/auditor — дешёвая DeepSeek flash; developer — cursor-acp. Дорогой инструмент только на генерации кода, всё остальное — копейки.
- Контраст со схемой «одна дорогая модель на всё»: она делает и то, что дешёвая сделает не хуже. Fleet — это ещё и экономика: платите за код, а не за болтовню.

### О5. Человек — контролёр развилок, а не оператор клавиш
- Эскалация по типу: needs_environment (директор сам ставит тулзу) / needs_decision (человек) / ambiguity (человек). Человек входит в петлю только на развилках.
- «Окно видит пользователь» — всё выполнение наблюдаемо: сессии в ~/.pi/agent/sessions/, трейсы в Phoenix, связь — файл сессии. Не чёрный ящик.
- git commit/push — только после прямой команды человека. Машина не имеет права финализировать.

## 3. Черновик текста (расширение гл. 7 или заготовка следующего ролика)

Почему у меня не один агент, а фабрика? Потому что контекст — не свалка, а эстафета.

Claude Code, Cursor — это один гений в одном чате. В начале задачи голова чистая. К середине он тащит всё: бизнес-требования из первого часа, синтаксис скобки из прошлого, три своих же галлюцинации, которые вы уже обсуждали и похоронили. Context Rot. Рюкзак один — и он пухнет.

Фабрика решает это иначе. Контекст живёт не в чате — в файлах. Задача — бриф. Переговоры — доска. Результат — отчёт с вердиктом. Каждый агент заходит в задачу и читает свой кусок. Только свой. Аналитику не нужны скобки. Разработчику не нужны бизнес-требования целиком — ему нужен бриф и спека. Контекст не наследуется по цепочке — он передаётся по эстафете. И файл, в отличие от чата, можно перечитать, закоммитить и отдать следующему.

Второе. Это не «много агентов» — это граф вызовов. Директор принимает заказ и пишет бриф. Простой кейс — один исполнитель по таблице ролей. Сложный — лид собирает состав: аналитик, дизайнер, разработчик, тестер. Проект изменился — техрайтер приводит документацию. И последним всегда заходит аудитор. Не потому что он умнее — потому что он чужой. Его работа — сломать то, что сделал коллега. Найти ту самую скобку, тот самый левый пакет в зависимостях. PASS он подписывает не верой, а сигналом: вот вывод grep, вот номера строк. Не «токены обновлены» — а «токены обновлены, вот доказательство».

И у бреда есть бюджет. Один FAIL — агенту дают один повтор. Второй FAIL — вопрос уже человеку. Третье окно не открывается. Саморефлексивная спираль не раскручивается, потому что ей не дают.

Третье. Экономика. В моём комбайне дорогой инструмент стоит только там, где пишется код. Всё остальное — чтение репо, спеки, тесты, документация, аудит — делает дешёвая модель. В схеме «одна дорогая модель на всё» вы платите премиальную цену и за то, что флэш-модель сделала бы за копейки. Fleet — это не только архитектура. Это счёт.

И заметьте: человек здесь — не оператор клавиш. Он контролёр развилок. Машина сама справляется с окружением. Человека зовут, когда нужно решение. И финализировать работа машины не имеет права: коммит — только после прямой команды.

[Пруф из жизни: Encraw. За вечер фабрика вскрыла транспорт Яндекс Музыки. В отчёте в .factory/goals — AES-128-CTR поверх всего файла, ключ из file-info, подпись HMAC-SHA256, гамма привязана к абсолютному оффсету, структура боксов fMP4, референсный CLI без зависимостей и 26 тестов на реальных байтах. Каждый шаг оставил артефакт в репо — это и есть эстафета, а не чат. ПРОВЕРИТЬ у автора: кто из ролей что делал в этом прогоне — в тексте роли не расписаны.]

## 4. Digest источников — что забрать и куда

### Карпатый в Sequoia → гл. 4 (призраки), гл. 6, финал
- «Призраки, не животные»: поведение модели сформировано претрейном и функцией награды — нет ни мотивации, ни любопытства, ни удовольствия. → ГЛ. 4, к «цифровому памятнику»: «Модель — не зверь, которого дрессируют. Призрак данных. Мы смотрим в зеркало — и видим призрака». Рифмуется с финальным «зеркалом датасета».
- Software 3.0: промпт и контекстное окно — способ программировать модель; Software 1.0 — код, 2.0 — веса, 3.0 — промпт. → ГЛ. 6, к «промпт — основной язык».
- «Агенты вместо установщиков»: инструкция, которую агент сам осматривает, адаптирует и чинит — сильнее скрипта. → ГЛ. 6, к SDD-блоку.
- Приложения отомрут, где модель делает прямое преобразование входа в выход (фото меню → меню с картинками). → ГЛ. 6, к «инди-киллерам»: смерть не только мелких утилит, но и целых приложений-прослойек.
- Неравномерность способностей: сильны там, где проверяемо (математика, код); проваливаются вне распределения. → уже закрыто RLVR-блоком гл. 4, можно не дублировать.
- Компании могут строить свои RL-среды и дообучать под себя. → ГЛ. 8/финал: ответ вендору — своя среда проверки.
- Найм: не puzzle-собеседования, а «построй большой проект агентами и попробуй сломать его агентами». → ФИНАЛ, «Куда смотреть».
- Агентный код bloated, repetitive, fragile — люди всё равно следят за качеством. → ГЛ. 6, поддержка тезиса «код = расходник, но качество — за человеком».
- Инфраструктура и документация построены для людей, не для агентов (деплой через десяток панелей и DNS). → ГЛ. 7/финал: «следующая война — за агентно-читаемую инфраструктуру».
- Агенты как представители: агент-секретарь одной компании договаривается с агентом-секретарём другой. → ФИНАЛ, визионерская строчка.

### Автореференты → гл. 5 (финал, после «самого радикального»)
- Gödel Agent (Yin et al., ACL 2025): агент читает и переписывает свой код на рантайме — включая логику, которой переписывает. Первый прямой потомок машины Гёделя Шмидхубера: доказательство заменено оценкой.
- Darwin Gödel Machine (Zhang et al., Sakana/UBC, ICLR 2026): эволюционный архив версий; SWE-bench 20% → 50%, Polyglot 14% → 31% — самоулучшение работает в рамках бенчмарка.
- HyperAgents (Meta, 10.2026): мета-агент правит и себя, и таск-агента; сама процедура правки — редактируемая. «Метакогнитивная самомодификация».
- Athanor (11.2026): команда frontier-агентов автономно пост-трейнит сырую базовую модель до уровня официальной instruct-версии — SFT, RL, мерджи весов друг друга, самодистилляция. «Перекомбинирование известных методов».
- AIDE²: AI-research агент рекурсивно улучшает собственный harness, прирост переносится на исследовательские задачи.
- ЗАНОЗА 1 — The Self-Improvement Problem (10.2026): доказано — не существует терминирующей процедуры, одновременно гарантирующей надёжность (не принять ухудшение) и полноту (не пропустить улучшение). Полностью безопасное самоулучшение математически невозможно.
- ЗАНОЗА 2 — обзор 249 работ (Springer, Cluster Computing): Recursive Self-Improvement–Safety Paradox — чем лучше система самоулучшается, тем критичнее ниже её безопасность; Scalability-Coordination Dilemma — мультиагентные бенефиты деградируют с масштабом.
- Куда: финал гл. 5 уже говорит «сеть, которая учится менять правило своего же изменения». Автореференты — следующая ступень той же лестницы: от весов к коду самого агента. И обе занозы — теорема и парадокс — усиливают стену гл. 4: даже когда лаборатории ломают барьер обучаемости, барьер надёжности остаётся математическим.

### Флот-инструменты (видео «Продуктивного Совета») → гл. 7 (один абзац после «открытого мира»)
- Herdr — «Tmux для агентов»: держит агентов в фоне, статусы в сайдбаре, интерфейс из файлов (модится самими агентами), агенты общаются с агентами.
- Orca — ADE, Agent Development Environment: git-worktree на сессию — агенты работают над одним проектом не наступая друг на друга.
- Paperclip — «компания агентов»: орг-чарт, бюджеты, тикеты, SEO-агент делегирует подчинённым.
- agentmemory / Hindsight — общая память между харнессами: Codex знает, о чём вы договорились с Claude.
- Buzz (Block) — агентный чат по Nostr: каналы, треды, упоминания, агент передаёт задачу агенту.
- Смысл вставки: «флот — не моя причуда, рынок уже строит стаи»: закрытые коробки сливаются в рой, а рой требует того же, что и моя фабрика — статусов, памяти, изоляции.

### SQLite FTS5 / BM25 вместо RAG → финал («Куда копать», второй мозг)
- Три способа дать модели память: всё в контекст / векторная база с RAG / ключевой поиск. Векторная база — дорого (эмбеддинги, инфраструктура, ломается при смене модели).
- BM25 просто: редкость слова, повторы, длина текста. SQLite + FTS5 — один локальный файл, топ-8 за 0.1с без единого вызова LLM.
- Дешёвая модель заранее пишет карточки (саммари + поисковые вопросы + ключевые слова), поиск ранжирует карточки; свежесть: вес записи падает вдвое каждые 120 дней.
- Гибрид — лучшее из двух: BM25 ловит точные имена, пути, IP; векторы — парафразы; склейка через RRF. (Бенчмарки 2026: на точных терминах BM25 часто не хуже векторов.)
- Рифма с финалом: брифы, ADR, логи, эвалы — это уже markdown-карточки. Второй мозг автора фактически уже BM25-совместим: файлы + дисциплина вместо магии эмбеддингов.

## 5. Честные контр-поинты (держать в голове для защиты)
- Scalability-Coordination Dilemma: мультиагентность не серебряная пуля — бенефиты деградируют с масштабом. Ответ ролика: поэтому граф и роли, а не «больше агентов».
- Агентный код раздут и хрупок (Карпатый). Ответ: поэтому аудитор и DoD с сигналом.
- RSI-Safety Paradox + теорема о самоулучшении: нельзя дать машине улучшать себя и гарантировать безопасность одновременно. Ответ: человек — контролёр развилок, коммит — только по команде.
- Оверхед фабрики на мелкой задаче. Ответ: режим «Сам рулишь» — один исполнитель, без lead; фабрика масштабируется вниз до одного агента, Claude Code — вверх не масштабируется.
